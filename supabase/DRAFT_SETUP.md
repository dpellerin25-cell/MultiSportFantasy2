# Test-project startup draft setup

This privileged administrative CLI prepares an unstarted rehearsal draft in
`MultiSportFantasy-Draft-Test` (`tgvuntuhdqucazpoxrrg`). It is not the future
commissioner-facing API. No login flow, account mapping, commissioner grant,
website page, timeout worker or production connection is introduced.

No new migration is needed for this step. The four existing migrations,
including snapshot guards, must already be applied. Transfer the new setup
scripts, tests, package.json and docs to Codespaces through your usual process.
Nothing has been committed, pushed or run against hosted Supabase by this task.

## 1. Test and create a configuration template

In the same Codespaces terminal with your verified database settings:

```bash
cd /workspaces/MultiSportFantasy2/supabase/tests
npx --yes pnpm@11.25.0 test
node setup-draft.mjs --template /tmp/startup-draft.json
code /tmp/startup-draft.json
```

The template includes a new draft UUID and your successfully imported pool:
`e159f9bf-6527-4333-b6b2-d6341ee22fcf`. Keep the generated draft UUID so retries
identify the same draft. Template creation refuses to overwrite an existing file.
Save a copy of the completed configuration somewhere persistent; `/tmp` may be
cleared. It contains no credentials.

Choose `timer_seconds` (1–86400) and replace the empty `owner_order` array with
all nine owner slugs in the commissioner-chosen ROUND ONE order:
`brendan`, `chris`, `doug`, `hatch`, `jack`, `jacob`, `nik`, `ryan`, `tucker`.
These names are an inventory, not a recommended order. Use JSON double quotes
around each slug, commas between entries, and no trailing comma. The template's
name/year are editable. Press Ctrl+S to save. The tool refuses a blank order or
timer. Round count is fixed at 65 and the roster minimums remain NFL9, NBA8,
MLB14, EPL11, PGA6, without sport maximums.

## 2. Preview without writing

```bash
export DRAFT_TEST_CONFIRM=tgvuntuhdqucazpoxrrg
NODE_EXTRA_CA_CERTS="$HOME/.config/multisport-draft/supabase-ca.crt" \
  node setup-draft.mjs --preview /tmp/startup-draft.json
```

`DRAFT_TEST_DATABASE_URL` must still be exported in this terminal. The preview
uses a read-only database transaction. Review the owner order, timer, snapshot
date, sport counts, first two rounds, and final round. It validates enough total
players for 585 picks and enough per sport for nine owners' minimums. It does
not re-fetch Fantrax or guarantee the saved snapshot is still current.

## 3. Save the unstarted rehearsal draft

Once the preview matches your choices:

```bash
NODE_EXTRA_CA_CERTS="$HOME/.config/multisport-draft/supabase-ca.crt" \
  node setup-draft.mjs --create /tmp/startup-draft.json
```

Expected output: `status: "setup"`, `started: false`, `scheduled_picks: 585`,
`persisted_pick_slots: 0`, plus counts and previews. Actual pick slots will be
generated by the existing authorized start command later; generating them now
would freeze the order too early and conflict with that start command.

The setup creates the draft, nine participants, a copy of every eligible player
in the chosen snapshot, automatic minimum rules, and an `admin_setup` audit event
in one transaction. The event explicitly identifies privileged administrator
setup rather than pretending that Doug authenticated. No deadline or active
pick is set. Existing website/Fantrax rosters are untouched.

Repeat the same create command to verify `already_exists: true`. The draft UUID
is the retry key. Matching retries also check saved order, rules and pool contents.
Different settings under the same UUID, previously generated slots, or a draft
that has started are rejected. This initial tool intentionally does not overwrite
an existing setup; a future commissioner editing workflow will use the existing
authorized commands. Do not generate a new UUID just to retry an uncertain result.

## Verification and limits

Offline tests cover the snake sequence and 65 picks per owner, invalid configs,
inactive owners, missing/unpopulated imports, read-only preview, atomic creation,
snapshot copy, no start/clock/pick-slot generation, retry safety, conflicting
settings, started-draft rejection, injected failure rollback, and no account grants.
Creation calls serialize through a transaction-scoped advisory lock and lock an
existing draft. These new setup paths have not yet been exercised concurrently
against hosted PostgreSQL. SQL administrators remain trusted.

After hosted rehearsal setup, the next stage is the authenticated application
API and owner access, followed by shared updates, automatic timeout processing,
and eventually the draft room UI. Do not start a real draft with this tooling.
